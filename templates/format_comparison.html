Same audio, two ways to describe it

A caption describes how a voice sounds. A transcript records the words spoken. A vocal burst is a nonverbal vocal event, such as a laugh, gasp or sigh. This page compares descriptions and predicted event intervals; an event marker is a model proposal that you can check by listening.

Procedural: acoustic scores → rules → text

  1. Humaneness Ears Medium predicts emotion, voice-style and quality scores, plus vocal-event intervals and type labels.
  2. Parakeet v3 supplies recognized words and their timestamps.
  3. Deterministic rules select distinctive properties and write GENERAL / SCRIPT, with timed speech, pauses and event labels.

The writer uses no generative language model. The selected event threshold is 0.7.

MOSS: audio + selected intervals → descriptions

  1. Voice Captioner receives the complete recording and writes the overall caption.
  2. Humaneness Ears Medium supplies the proposed start/end times. MOSS does not discover these timestamps.
  3. Vocal Burst Captioner receives the complete audio and both endpoints for each selected event, producing its free-form description.

The MOSS captioners receive neither intended emotions nor the performance script. The selected event threshold is 0.6, with greedy decoding.

The pipelines share the original audio and acoustic locator, but use different selection thresholds. Consequently, they can show different event counts: __PROC_EVENTS__ procedural intervals and __MOSS_EVENTS__ MOSS intervals across these 50 recordings. Neither pipeline caps the number of selected events.

MOSS gave more faithful voice and event descriptions on this listening set under the shared rubric. Procedural captions expose their score selection and formatting rules, but their generic event names and attribute wording received lower fidelity ratings.

This is a small, English-heavy study of synthetic acting audio, reviewed by one automated audio judge, not a human benchmark or a claim about every recording. The shorter procedural default and the previous prose setting tie overall at 2.704/5.

What are GENERAL / SCRIPT and CAPTION / TRANSCRIPT?

These are text formats for storing voice-training annotations. GENERAL and CAPTION describe the recording; SCRIPT and TRANSCRIPT carry its words and optional timing cues. The existing procedural format uses:

GENERAL: A softly spoken, hesitant voice with restrained sadness.
SCRIPT:
(soft, hesitant, sad) [2.10 seconds duration] I thought you might stay.
[0.40 seconds pause]
(Chuckle, 0.30 seconds)

Illustrative format example, not a model prediction for one of the recordings above. Speech durations and pauses use square brackets; event labels and durations use round brackets. Every event also retains its exact start/end timestamps in the saved JSON.

The selector under each card offers six existing MOSS exports: two caption choices × three transcript choices. The caption is either the original whole-recording MOSS prose, or that prose followed by detailed event descriptions. The transcript is plain ASR, ASR with inline event labels, or a verified timed script.

The current inline event tokens contain type labels, not the full MOSS burst prose. Free-form descriptions are presently appended in the detailed-caption variant. The original whole-recording prose can itself mention bursts, even in “whole-recording caption only.”

The duration, word-order and selected-event count checks passed for all 38,427 successfully generated English/German recordings in the released dataset. This verifies formatting against saved intervals, not acoustic detection accuracy. Unsupported alignment is reported explicitly.

How settings were chosen and ratings obtained

Four procedural configurations were compared on 25 language-stratified selection recordings. Compact tags tied the longer tags setting, so the shorter configuration was selected and frozen before checking the other 25 recordings. The previous prose setting slightly outscored compact tags on confirmation, 2.772 versus 2.760. This does not establish a unique optimum.
